## Code Prover

**Green: 29, Orange: 0, Red: 0 — 100% proven**, with input ranges bounded to a physically realistic sensor domain (`polyspace/drs.xml`: `alt_cmd`, `alt_meas`, `vz_meas` ∈ [-10000, 10000], generous relative to the validity gate's [0,500]/[-15,15]).

Without that bound, Code Prover reports 2 Orange (unproven) float-Overflow checks on the `alt_cmd - alt_meas` subtraction and the `Kp * error` multiplication — because with `-main-generator`'s default unconstrained-double inputs, Code Prover correctly cannot rule out overflow for values approaching `DBL_MAX`. This is not a false positive: the code does compute `rtb_AltitudeError = alt_cmd - alt_meas` *before* the validity gate runs, so genuinely out-of-domain sensor values could in principle reach that arithmetic. Constraining the input domain to the sensor's actual physical range (rather than the full mathematical range of the C `double` type) is the standard Code Prover disposition for this pattern, and is what was applied here.
